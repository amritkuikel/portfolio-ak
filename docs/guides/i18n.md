# Internationalisation (English + Nepali)

Every string, email, validation message, head tag and formatted value exists in both languages. Example: `/dev/examples/i18n`.

## Messages

- **Files:** `messages/en.json` and `messages/ne.json`, compiled by Paraglide into `src/paraglide/` (generated, gitignored) on `dev`, `build`, `test` and `typecheck`. The inlang plugins are pinned devDependencies loaded from `node_modules` (`project.inlang/settings.json`), so compiling needs no network (0157).
- **Output:** one module per locale in dev, tests and `pnpm typecheck` (`paraglide.config.ts`); production builds switch to one module per message (`vite.config.ts`) so each page ships only the messages it uses (0155).
- **Adding a message:** write it in `messages/en.json`, then `pnpm i18n:translate` fills the Nepali for every message that has none (`inlang machine translate`; existing translations are never touched). Review the diff: set `INLANG_GOOGLE_TRANSLATE_API_KEY` for Google's quality, because without a key the CLI uses a community-run service whose Nepali can be wrong. `pnpm i18n:check` (CI) reports missing or empty translations, missing variables and plural forms.
- **In code:** `import { m } from "@/paraglide/messages"`, then `m.things_title()` or `m.things_count({ count: formatNumber(n) })`. Format numbers before passing them in.
- **Call `m.*()` at render time.** A string or JSX built at module level is frozen in the first request's language on the server. Passing the function itself is fine (`staticCrumb(m.things_title)`, label maps of `() => string`).
- **Tests** (`tests/i18n/`): both files have the same keys and placeholders; no Nepali message is a copy of the English one (except endonyms and pure formats); every key is used somewhere in `src`. Delete keys whose UI is gone.
- **Server code** uses `m.*` too. Server functions get the page's locale through a header (`localeFunctionMiddleware`), so field errors come back in the user's language. Emails take the recipient's locale explicitly (`sendEmail({ …, locale })`).

## URLs and routing

- **English** is unprefixed (`/things`); **Nepali** lives under `/ne` (`/ne/things`). Routes are defined once; the router rewrites `/ne/…` onto them (`project.inlang/paraglide.config.ts`, `src/router.tsx`). Links stay unprefixed in code and are localized on the way out.
- **The language switcher** links to the same page in the other language. `<html lang dir>` follows the locale.
- **Head tags** carry `hreflang` alternates for both languages plus `x-default` (English); see [seo.md](seo.md).

## Formatting

Use `src/lib/i18n/intl.ts`, never `Intl` directly:

| Function | Notes |
| --- | --- |
| `formatDate`, `formatDateTime`, `formatMonthYear`, `formatWeekdayShort` | In `Asia/Kathmandu` |
| `formatNumber`, `formatCurrency` (NPR by default), `formatBytes` | Devanagari digits in Nepali |
| `formatRelativeTime`, `formatRelativeTimeFrom(date, now)` | Pass a fixed `now` when the value is rendered on the server, or hydration can mismatch |
| `parseLocaleNumber` | Accepts Devanagari digits and separators (used by the number fields) |

Browsers like Chrome ship without Nepali locale data, so raw `Intl` output differs between the server and the browser. `src/lib/i18n/intl-ne.ts` builds the Nepali formats the same way on both.

**Dates in filters and forms** are calendar days (`"YYYY-MM-DD"`). They are compared as instants in the app's time zone (`src/lib/i18n/date-only.ts`, 0093).

## Fonts

Inter (Latin) and Noto Sans Devanagari, self-hosted variable fonts with metric-matched fallbacks. Production preloads the subsets each locale renders first (`src/lib/fonts.ts`); dev doesn't, so dev pages can shift slightly while fonts load.

## Adding a language

Add it to `project.inlang/settings.json` and its prefix to `paraglide.config.ts`, then create `messages/<code>.json` with every key (the parity test lists what's missing). After that, add its Open Graph locale (`OG_LOCALES` in `src/lib/seo.ts`), a `/<code>/manifest.webmanifest` entry in `vite.config.ts` and `/<code>/admin` in robots (`src/server/seo/robots.ts`), and number and date formats in `src/lib/i18n/intl.ts` if `Intl` lacks them.

## Pitfalls already solved

Moved here from CLAUDE.md, which keeps only the ones that apply everywhere. Don't reintroduce them.

- **Fonts are never inlined:** a font file under Vite's 4 kB limit would become a `data:` URL, which the CSP's `font-src 'self'` blocks. `vite.config.ts` turns inlining off for `.woff`/`.woff2` (0108).
